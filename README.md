# 🦉 Сова-юрист

Автоматизация юриста по взысканию задолженности за ЖКУ. Локальное desktop-приложение
на Python + Tkinter: превращает расчёт бухгалтерии и сканы справок Ф-9 в готовые
судебные приказы и исковые заявления.

Работает **только на вашем компьютере**. Интернет не используется, персональные данные
никуда не отправляются.

Три раздела:

| Раздел | Что делает |
|---|---|
| **Жилищное право (ЖКУ)** | Расчёт бухгалтерии («Портянка») + сканы справок Ф-9 → таблица ввода → судебные приказы и иски (.docx) + реестр и отчёт сверки. Номер лицевого счёта распознаётся **автоматически** из текста каждой справки; страница привязывается к своему счёту, а не «наугад». |
| **Семейное право** | Сканы (паспорт истца, свидетельство о браке, свидетельства о рождении детей) → анкета → иск о расторжении брака, взыскании алиментов и определении места жительства детей. |
| **Защита прав потребителя** | Сканы (паспорт, претензия, чек) → анкета → иск: возврат денег / замена / устранение недостатков + неустойка + моральный вред + штраф 50 %. |
| **Досудебные претензии** | Список Excel (лицевой счёт, ФИО, адрес, сумма) → таблица → претензии: по одной на должника, каждая с новой страницы, всё в одном файле Word. |

## Досудебные претензии

Раздел работает как остальные: список → таблица → документы.

1. **Загрузить список** — файл Excel со столбцами «лицевой счёт, ФИО, адрес, сумма»
   (шапки может не быть). Можно выбрать вместе с ним и свой шаблон претензии `.docx` —
   он подхватится и будет использоваться дальше.
2. **Открыть таблицу** — `pretension-input.xlsx`:
   - лист **«Претензии»** — список претензий; строки можно править и удалять,
     по строке задать свой номер, дату и период;
   - лист **«Настройки»** — реквизиты взыскателя (шапка), исходящий номер и дата
     претензий (например `100 от 10.11.2026`), дата, на которую считается долг,
     период задолженности, срок оплаты.
3. **Собрать документы** — все претензии в одном файле Word, по одной на должника,
   каждая с новой страницы. Имя файла — по исходящему номеру и дате:
   `Претензии № 906 от 24.11.2026.docx`. Рядом — `registry.xlsx` и отчёт сверки.

Претензии отправляются **пакетом**, поэтому исходящий номер и дата в шапке
«№ … от …» — общие на все претензии: их указывает сотрудник в листе «Настройки»
(`исходящий_номер_и_дата`), автоматическая нумерация не используется.
Если дата состояния не задана, претензия считается по состоянию на 1-е число
месяца исходящей даты: `100 от 10.11.2026` → «по состоянию на 01 ноября 2026 года».
В строке адреса должника вписывается лицевой счёт (`- ЛС№…`), а почтовый индекс
подтягивается сам, если его нет в адресе (см. «База почтовых индексов РФ»).

Шаблоны претензий лежат в папке `pretension-templates/` и не содержат данных:
реквизиты взыскателя подставляются из листа «Настройки», данные должника — из списка.
Точные повторы (одна ФИО, адрес и сумма) по умолчанию пропускаются — настройка
«точные повторы пропускать».

## Включение и выключение разделов

Разделы включаются флагами из файла `features.json` рядом с программой:

```json
{
  "семейное_право": false,
  "защита_прав_потребителя": false,
  "договоры": true
}
```

`true` — раздел виден, `false` — скрыт. По умолчанию файла нет — показываются все
разделы. Флаги читаются по порядку: значения по умолчанию → `features.json` рядом
с программой → `~/.config/sova-yurist/features.json` (ваш файл, перекрывает
предыдущие) → переменная окружения `SOVA_FEATURES` (JSON-строка).

В этой сборке разделы «Семейное право» и «Защита прав потребителя» выключены —
данные и генераторы для них на месте, шаг сборки документов не запускается.

## Установка

### Linux (Debian / Ubuntu / Mint)

```bash
bash install-linux.sh
```

Скрипт поставит зависимости, скопирует программу в `~/Desktop/OwlLawyer`, создаст
ярлыки «Сова-юрист», «1 Загрузить данные», «2 Собрать документы» и проверит
цепочку демо-прогоном.

Если зависимости уже стоят: `SOVA_SKIP_APT=1 bash install-linux.sh`

### Windows

Запустите **`SOVA-Setup-0.2.1-x64.exe`** (Windows 10/11, x64).
Мастер проверит Python/Tkinter, подготовит отдельное окружение с библиотеками
и предложит установить отсутствующие Tesseract OCR, Poppler и LibreOffice.
Русская модель OCR включена в установщик. Для загрузки недостающих компонентов
нужен интернет; сама программа обрабатывает документы локально.
Поддерживается Windows 10 1803 (сборка 17134) и новее. Если WinGet недоступен,
установщик использует проверенные прямые загрузки компонентов.

Из исходников можно запустить `install-windows.bat` — он использует те же проверки
и спрашивает об установке недостающих компонентов и LibreOffice.
Пошагово — [`windows-installation.txt`](windows-installation.txt),
сборка установщика — [`packaging/windows/README.md`](packaging/windows/README.md).

### Зависимости

Python-библиотеки — [`requirements.txt`](requirements.txt):

```bash
pip install -r requirements.txt
```

Внешние программы: `libreoffice` (конвертация в PDF/Word), `tesseract-ocr` + `tesseract-ocr-rus`
(распознавание Ф-9), `poppler-utils` (`pdftoppm`, `pdfunite`, `pdftotext`).

## Как пользоваться

При запуске из репозитория: `.venv/bin/python app/desktop_app.py`.
Папка входящих файлов — `incoming/`; после установки — `~/Desktop/filing/incoming/`.
Программа создаёт папки `output/`, `output-family/`, `output-consumer/`,
`output-contracts/`, `scans/`, `scans-family/`, `scans-consumer/` и
`contract-templates/` внутри папки приложения по мере использования.

1. Откройте СОВА и выберите направление в боковой панели.
2. **«Выбрать файлы»** — загрузите расчёт и сканы для распознавания.
3. **«Открыть таблицу / анкету»** — проверьте данные и сохраните исправления.
4. **«Создать документы»** — получите документы в папке `output/` соответствующего раздела.
   Проверьте `validation-report*.txt` и откройте документы в Word / LibreOffice.

Расчёт («Портянка») читается **со всех листов** книги: в каждом листе ищется
таблица портянки (строка заголовков «№ п/п»), блоков в одном листе может быть
несколько. Листы без такой таблицы пропускаются — об этом пишется в отчёт
импорта.

### Какая форма документа собирается

По умолчанию — **судебный приказ**. Исковое заявление собирается только когда:

- долг с пеней больше 500 000 ₽ (ст. 121 ГПК РФ — приказ в такой сумме невозможен);
- судебный приказ отменён — в листе «Заявления» в колонке «Отмена СП (да/нет)» вписано «да»;
- в «Портянке» в колонке «Тип» прямо указан иск.

Категория должника из справки Ф-9 (наниматель / собственник) задаёт **правовое
основание** документа — текст мотивировки и строку «Руководствуясь», а не его форму.

### Как называются файлы и что записано в шапке

Готовый документ называется по-русски:

```
21 судебный приказ собственник Иванов И.И. ЛС 6200001.docx
```

то есть номер, форма документа, статус ответчиков, Фамилия И.О. и лицевой счёт.
В шапке самого документа эти данные **не печатаются** — она заканчивается
реквизитами взыскателя, ценой иска и госпошлиной, дальше идёт заголовок документа.
Те же данные идут отдельными колонками в реестр `registry.xlsx` («Форма документа»,
«Статус ответчиков», «Ответчики (Фамилия И.О.)», «Адрес», «Лицевой счёт»).

Реквизиты взыскателя в настройках можно заполнять как с подписью («Юр.адрес: …»,
«Тел. …», «р/с … к/с …»), так и без неё — подпись в документе не задваивается.

### Суд в шапке документа

Суд берётся **из таблицы**, в таком порядке:

1. лист «Справочник ЛС» — суд для конкретного лицевого счёта;
2. прежняя книга — если по этому лицевому счёту суд уже заполняли;
3. настройка **«суд (шапка)»** — суд подачи, вписывается один раз и подставляется
   во все заявления, где свой суд не указан;
4. только если ничего из этого нет — условный демонстрационный суд по типу
   документа, и тогда в отчёте импорта будет предупреждение: такой суд в реальную
   подачу отправлять нельзя.

Настройки юриста (наименование взыскателя, адреса, банк, суд) **переживают
переимпорт**: книга пересобирается с нуля, но значения переносятся из прежней
книги — вводить их заново после каждой загрузки не нужно.

### Суд и почтовый индекс — по адресу ответчика

Суд в шапке и почтовый индекс в адресе ответчика можно получать **автоматически**
по данным ГАС РФ «Правосудие» (sudrf.ru) — открытого источника без регистрации
и ключей:

* адрес ищется в ФИАС (подсказки адреса) — оттуда почтовый индекс и идентификатор
  адреса для подсудности;
* по этому идентификатору определяются суды: судебный участок (мировой судья),
  районный, областной, апелляционный;
* **СП** (судебный приказ) → судебный участок, то есть мировой судья
  (ст. 121 ГПК РФ); **ИСК** → районный суд, а если цена иска не больше порога
  (50 000 ₽, ст. 23 ГПК РФ) — мировой судья;
* в шапку добавляется строка с адресом суда, а в адрес ответчика — почтовый индекс.

Ответы кэшируются в `~/.cache/owl-lawyer/sudrf.json`: повторный сбор документов
на сайт не ходит. Если сети нет или сайт не отвечает, приложение работает как
раньше — берётся суд, указанный юристом вручную, а в отчёт пишется
предупреждение.

Настройки листа «Настройки»:

| параметр | что делает |
|---|---|
| «подсудность (авто)» | да/нет — определять суд по адресу (по умолчанию да) |
| «индекс в адресе» | да/нет — дописывать почтовый индекс в адрес ответчика |
| «порог мирового судьи, руб.» | до какой цены иска — мировой судья (по умолчанию 50 000) |

Указанный вручную суд при этом не затирается молча: если суд по адресу отличается
от указанного вручную, в отчёте сверки будет предупреждение с обоими вариантами.

Проверить один адрес вручную:

```
python3 app/sudrf_lookup.py "Московская область, г. Пример, ул. Тестовая, д. 1"
```

### База почтовых индексов РФ — в комплекте

В программу вложена локальная база всех почтовых индексов страны: **61 208
индексов** из эталона «Почты России» (ОПС; выгрузка обновляется раз в две недели).
Если в адресе индекса нет, приложение подтягивает его само:

1. сначала локальная база — `app/data/postal_base.json.gz` (населённые пункты)
   и `app/data/postal_streets.txt.gz` (улицы для городов, где индексов много);
2. в крупных городах, где индекса населённого пункта мало, — уточнение по дому
   через ФИАС (ГАС «Правосудие»), затем сайт «Почты России».

База лежит в комплекте и работает **без сети** — при недоступных сайтах индекс
всё равно найдётся по населённому пункту. Обновить базу, когда выйдет свежая
выгрузка ОПС:

```bash
python3 build_postal_base.py
```

Индексы подтягиваются при сборке **любых** документов: претензий, исков по ЖКУ,
исков о защите прав потребителя и семейных исков. В претензии в строку адреса
должника дополнительно вписывается лицевой счёт («- ЛС№…»).

На Windows входящие файлы можно хранить в `incoming/` внутри папки установки
(`%LOCALAPPDATA%\Programs\OwlLawyer` по умолчанию).

Полный цикл показывает демо-набор в `incoming/demo/` — все данные в нём
**вымышленные**: компания «ООО „Рога и Копыта“», адреса «Примерная область, Примерный
район, г. Пример», паспорта `40**-******`, счёт `407028****2345`. Печать на демо-справках
нарисована с нуля.

## Приватность

- Программа не шлёт телеметрию и не отправляет ваши данные: в сеть уходит только
  адрес, который уточняется по ГАС «Правосудие» и сайту «Почты России» (суд и
  почтовый индекс). Остальное — база индексов в комплекте, работает офлайн.
- **Персональные данные должников в репозиторий не попадают** — таблицы ввода, сканы
  Ф-9, распознанные паспорта и папки `output*` исключены в `.gitignore`.
- Всё демо-контент в репозитории — вымышленный. Реальные данные живут только в вашем
  рабочем каталоге.
